Agent-facing project memory. Keep it short, keep it true. Hardware facts are
NOT up for guessing — see the verified source of truth below.

## What this is

Automated catfish-pond feeder, two PlatformIO firmware projects:

- **Display Unit** — Waveshare ESP32-S3-Touch-LCD-4.3B (ESP32-S3-WROOM-1-N16R8,
  16 MB QIO flash, 8 MB octal PSRAM, 4.3" 800x480 RGB565 + GT911 touch +
  CH422G IO expander). Pond dashboard/UI. Env `display-unit`, pioarduino
  platform 55.03.312 (Arduino core 3.3.x).
- **Relay Unit** — ESP8266 NodeMCU V3 + 5 V 1-ch optocoupler relay driving the
  feeder motor (auger/roller). Env `relay-unit`, `espressif8266@^4.2.1`.

## Hardware truth

- `docs/notes/hardware-4.3b.md` is the **source of truth** for every pin,
  timing, expander index, and I2C address. Do not guess; read it.
- RGB565 bus, GT911 touch (SDA 8/SCL 9, INT 4), CH422G @ 0x20 (TP_RST=EXIO1,
  backlight DISP=EXIO2 — on/off only, NOT PWM, LCD_RST=EXIO3, SD_CS=EXIO4),
  TF 11/12/13, RS485 43/44, CAN 15/16, USB GPIO19/20 reserved.
- LVGL v8 API is REQUIRED (port files are v8): `lv_scr_act()`, `lv_btn_create()`, …
  Any LVGL call from a non-LVGL task must be wrapped in
  `lvgl_port_lock(-1)` / `lvgl_port_unlock()`.
- Relay side: relay driver D1 (GPIO5), status LED D4 (GPIO2, active low);
  many relay modules are ACTIVE-LOW (configurable); flyback diode 1N4007
  across the motor; common GND between units.

## Build / flash / monitor

```bash
pio run -d firmware/display-unit          # build ESP32-S3
pio run -d firmware/relay-unit            # build ESP8266
pio run -d firmware/<dir> -t upload       # flash over USB
pio run -d firmware/<dir> -t monitor      # 115200 baud
```

Build outputs land in `firmware/<dir>/.pio/build/<env>/`.

## Unit-to-unit protocol (HTTP JSON, LAN)

- Display Unit owns Wi-Fi provisioning (WiFiManager captive portal) and is the
  commander; Relay Unit is a thin HTTP server on the LAN.
- Payloads are JSON via **ArduinoJson v7** (both sides depend on
  `bblanchon/ArduinoJson@^7.4.2`, `tzapu/WiFiManager@^2.0.17`).
- Contract owned by firmware tasks 4-a/4-b; keep endpoints simple JSON
  (command + status), keep field names stable across both firmwares, and
  update this section when the endpoint set lands.

## CI, Pages, web flasher

- Workflow `Firmware` (`.github/workflows/firmware.yml`): builds both units on
  push/PR/tags/dispatch; `deploy-pages` (main only) publishes the web flasher;
  `release` attaches bins on `v*` tags.
- Pages URL: https://mlger.github.io/smartfishfeeder/ (Pages build_type
  `workflow`; official configure/upload/deploy Pages actions).
- ESP32-S3 needs a **merged binary** for browser flashing (ESP Web Tools can't
  patch flash params). CI merges with esptool v5 syntax (verified vs 5.6.0):

  ```bash
  esptool --chip esp32s3 merge-bin --output merged-firmware.bin \
    --flash-mode dio --flash-size 16MB \
    0x0 bootloader.bin 0x8000 partitions.bin \
    0xe000 boot_app0.bin 0x10000 firmware.bin
  ```

  (v5 renamed `merge_bin`→`merge-bin`, `--flash_mode`→`--flash-mode`;
  DIO chosen for max web-flash compatibility — board itself is QIO.)
- ESP8266 firmware is self-contained, flashed at offset 0 (single manifest
  part at 0).
- `web-flasher/manifest-*.json` committed defaults use `"version": "dev"` and
  are regenerated by CI with the real short SHA — keep them valid JSON.
- Manifest `chipFamily` must be exactly `ESP32-S3` / `ESP8266`;
  `new_install_prompt_erase: true` gives the erase-device prompt.
- CI artifacts: `fw-display-unit-<sha>` (5 bins), `fw-relay-unit-<sha>`.

## AI tooling

- `.mcp.json` (project-scoped, Claude Code): `context7` via remote HTTP MCP
  (`https://mcp.context7.com/mcp`, `"type": "http"` — a url entry without a
  type is invalid in Claude Code). Use context7 for library docs (LVGL,
  ArduinoJson, PlatformIO).
- `claude-mem` is a Claude Code **plugin**, installed per machine with
  `/plugin marketplace add thedotmack/claude-mem` + `/plugin install
  claude-mem`; it registers its own MCP server, so it is intentionally NOT in
  `.mcp.json`. Details: `docs/tooling.md`.

## Security rules (STRICT)

- NEVER commit tokens, PATs, API keys, or secrets — not in code, workflows,
  manifests, `.mcp.json`, or docs. No `Authorization`/key headers in any
  committed file.
- The GitHub PAT and Figma token used during setup must be rotated by the
  user (they appeared in session context only, never in the repo — keep it
  that way). Remind the user if they resurface.
- If a secret ever lands in the repo, treat it as compromised: rotate first,
  then clean history.
- The web flasher and manifests ship to a PUBLIC Pages site — nothing
  private belongs there.
